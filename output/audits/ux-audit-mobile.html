1. Login

Code terminal + PIN 6 chiffres — point d'entree unique

Point fort

Double layout mobile / POS terminal

Le login detecte le contexte (context.isPosTerminal) et affiche un layout centre pour telephone ou un split gauche/droite pour terminal POS avec bloc securite. Le bouton principal fait 56dp minimum — conforme Material 3.

Amelioration

PIN sans toggle de visibilite

Le champ PIN est toujours masque (obscureText: true) sans possibilite de devoiler. Pour un code numerique de 6 chiffres tape debout dans une boutique, les erreurs de saisie sont frequentes. Le machann doit retaper sans savoir quel chiffre etait faux.

Ajouter un suffixIcon toggle oeil ouvert/ferme sur le champ PIN.
Amelioration

Erreur de login toujours generique

Le AuthController retourne toujours la meme cle auth.login.error quel que soit le probleme (mauvais PIN, compte bloque, reseau). Le machann ne sait pas si son PIN est mauvais ou si le serveur est injoignable.

Distinguer au minimum 3 cas : mauvais identifiants, compte bloque (avec lien vers le dialog info), erreur reseau.
Point fort

100% i18n

Toutes les strings passent par translations.translate(). Le login est proprement traduit en creole, francais et anglais.

2. Akèy — Dashboard machann

Le tableau de bord quotidien : KPIs, tirages disponibles, dernier ticket

Point fort

Resume quotidien en 3 cartes stat

Ventes, tickets, commission du jour en haut — le machann voit son activite d'un coup d'oeil. Le badge online/offline pulse en vert/gris avec label texte. L'avatar en haut a droite ouvre le menu compte.

Point fort

Tirages avec countdown et bouton "Vann"

Chaque tirage disponible a une carte avec logo provider, nom localise, countdown avec code couleur (vert → orange → rouge selon urgence), et un bouton "Vann" direct. Le filtre par provider est masquable. Pull-to-refresh partout.

Amelioration

Timer 1 seconde reconstruit tout le sous-arbre

Un Timer.periodic de 1 seconde met a jour _now avec setState, ce qui reconstruit toutes les cartes tirage, les stats, et le dernier ticket. Sur un Sunmi V2 ou un telephone d'entree de gamme, c'est un probleme de performance.

Isoler le countdown dans un widget StreamBuilder separe pour que seuls les labels de temps soient reconstruits, pas l'arbre entier.
Amelioration

Section "dernier ticket" silencieuse en erreur

Si le dernier ticket ne charge pas ou n'existe pas, la section affiche un SizedBox.shrink() — rien du tout. Le machann voit le titre "Dernier ticket" avec du vide en dessous, sans message "Pa gen tikè jodi a".

Afficher un etat vide explicite : "Pa gen tikè vann jodi a" avec une icone ticket.
Amelioration

Avatar profil trop petit pour POS

L'avatar en haut a droite fait 52dp de large avec un label labelSmall en dessous. Sur un terminal POS ou le machann est debout, c'est difficile a toucher precisement. Le chevron a cote du bouton "Vann" fait 18dp — trop petit meme si c'est le fond de carte qui capte le tap.

3. Vann yon tikè — le flux critique

Selection tirage → jwèt → nimewo → miz → verifye → konfime — l'ecran ou le machann passe 80% de son temps

Etapes du parcours de vente
Tiraj pre-selectionne→ Chips jwèt→ Nimewo (segments)→ Miz (montan)→ Ajoute → repete→ Verifye (API)→ Konfime (API)
Point fort

Tirage pre-selectionne et auto-advance des segments

Si le machann arrive depuis le dashboard, le tirage est deja selectionne. Le champ de selection numerique avance automatiquement le focus au segment suivant quand il est rempli (2 chiffres → focus segment 2). Bon pattern pour la saisie rapide.

Friction

Chips de jeu sans feedback tactile

Les chips de selection de jeu (Bolèt, Maryaj, Loto) et les options de pari utilisent GestureDetector au lieu de InkWell. Pas de ripple, pas de retour haptique. Le machann tape un chip et ne sait pas si c'est pris — il doit attendre le changement de couleur de fond (qui depend du setState).

Remplacer GestureDetector par InkWell sur tous les chips interactifs pour avoir le ripple Material et le retour semantique screen reader.
Friction

Double confirmation Verifye → Konfime

La vente requiert 2 appels API distincts : prepare() (verification) puis confirmSell() (confirmation). C'est un choix de securite (eviter les ventes accidentelles), mais pour un machann qui vend 200+ tickets/jour, chaque tap supplementaire compte. Le bouton change de label entre les etapes, ce qui peut surprendre.

Option : un mode "vente rapide" dans les settings qui fusionne verifye+konfime en un seul geste pour les machann experimentes, avec un toggle dans les parametres.
Point fort

Undo inline pour les lignes supprimees

Quand le machann supprime une ligne du ticket, une barre undo inline apparait pendant 8 secondes (pas un SnackBar Material). C'est un excellent pattern — visible, non-intrusif, reversible.

Point fort

Preview ticket en temps reel

La carte preview en bas montre le total, les promotions (maryaj gratis), et les alertes en temps reel. Code couleur vert (accepte) / rouge (rejete) avec icone + texte. Le bouton "Copy diagnostic" en cas d'erreur est un bon pattern support.

Amelioration

Largeur selection fixe, risque de clip

Le champ de saisie numerique a une largeur fixe de 112px ou 152px selon le nombre de segments. Avec une taille de police grande (accessibilite) ou un ecran etroit (Sunmi 360dp), le contenu peut deborder.

Utiliser Flexible ou LayoutBuilder au lieu de largeurs fixes pour les champs de saisie.

4. Siksè vant — confirmation

Code ticket en grand, copie, impression, nouveau ticket

Friction

String francaise hardcodee : "Copier code"

A la ligne 197 de cashier_sell_success_page.dart, le label du bouton "Copy code" est hardcode en francais 'Copier code' au lieu de passer par le systeme i18n. Seul bug de localisation trouve dans toute l'app.

Remplacer par translations.translate('pos.sale.copy_code') et ajouter la cle dans les 3 locales.
Friction

"Nouveau ticket" renvoie a l'accueil, pas a la vente

Le bouton "Nouveau ticket" navigue vers /pos (dashboard) et non vers /sell. Le machann doit donc re-cliquer sur un tirage pour vendre a nouveau. Pour un vendeur en rush, c'est un tap de trop a chaque vente.

Naviguer vers /sell avec le meme tirage pre-selectionne (ou le dernier utilise).
Point fort

Code ticket en displayMedium w900 + auto-print

Le code est affiche en enorme (displayMedium, poids 900), tappable pour copier, avec impression automatique si le setting est actif. Le machann n'a qu'a donner le code au client — tout se fait automatiquement.

5. Istorik tikè — historique des ventes

Liste tickets aujourd'hui/hier avec recherche et reprint

Amelioration

Limite a aujourd'hui/hier, max 50 tickets

Le filtre date ne propose que "Jodi a" et "Yè". Un machann qui veut retrouver un ticket de la semaine derniere ne peut pas. La limite de 50 tickets (size: 50) tronque silencieusement les jours charges sans pagination.

Ajouter un date picker "Lòt dat" comme sur la page Rapports, et une pagination infinie (load more) au dela de 50.
Amelioration

Recherche par soumission clavier, pas live

Le champ recherche attend que le machann appuie sur le bouton "rechercher" du clavier (onSubmitted). Pas de filtrage en temps reel. Pour un code ticket de 6-8 caracteres, le filtrage live avec debounce serait plus naturel.

Point fort

Bouton reprint par ticket avec dialog raison

Chaque ligne a un bouton impression avec tooltip. Le clic ouvre un dialog de raison de reimpression. Bon pattern d'audit — on sait pourquoi un ticket a ete reimprime.

6. Tcheke tikè — verification

Scanner ou saisir un code pour verifier si un ticket est gagnant

Friction

Placeholder QR trompeur

Un grand placeholder avec icone QR (160dp) invite le machann a scanner. Quand il tape dessus, un snackbar dit "Scan pa disponib". C'est trompeur — l'affordance visuelle promet une fonctionnalite qui n'existe pas. Le machann perd confiance.

Aujourd'hui
  • Icone QR 56dp, opacite 30%
  • Texte invite au scan
  • Tap → snackbar "pa disponib"
Propose
  • Retirer le placeholder QR
  • Garder uniquement le champ texte
  • Ajouter label "Tape kòd tikè a"
  • Quand scan sera pret : ajouter le bouton
Point fort

Resultat code couleur avec severite

Le resultat de verification est une carte coloree : vert (gagnant/SUCCESS), orange (WARNING), rouge (ERROR). Avec icone, titre et message traduits depuis les cles serveur avec interpolation de parametres. Le bouton "Voir details" lie directement au ticket.

Amelioration

Bouton "Verifye" toujours actif meme si le champ est vide

Le bouton "Verifye" ne se desactive pas quand le champ de code est vide. Le machann peut taper "Verifye" sur un champ vide — le controlleur verifie en interne et ne fait rien, mais visuellement le bouton dit "je suis pret" quand il ne l'est pas.

Desactiver le bouton quand le champ est vide (onPressed: code.isEmpty ? null : verify).

7. Detay tikè

Receipt card avec lignes de jeu, montants, statut, reprint

Point fort

Format receipt familier

La carte imite un ticket de caisse : header avec code public (tappable pour copier), badge statut, heure, tirage, lignes de jeu avec selection preview, sous-total et total. Le machann retrouve visuellement le meme format que le ticket imprime.

Amelioration

Format date non localise

La date est formattee en dur DD/MM/YYYY HH:MM dans une methode _fmtDateTime. Ce format europeen est correct pour Haiti, mais pas adaptable si d'autres locales sont ajoutees. Le meme probleme existe sur la page notifications.

Utiliser MaterialLocalizations.formatMediumDate pour le formatage localise.
Amelioration

Pas d'action d'annulation

La page detail affiche le statut (y compris CANCELLED, VOIDED) mais ne propose aucune action d'annulation. Si c'est par design (annulation admin-only), le machann devrait voir un message "Pou anile tikè sa a, kontakte admin ou" au lieu de rien.

8. Rezilta tiraj — resultats des tirages

Lots gagnants avec filtres provider, slot et date

Friction

4 filtres empiles mangent l'ecran

Segmented button (7j/30j) + dropdown provider + dropdown slot + date picker = environ 300dp de filtres avant le premier resultat. Sur un ecran 720dp (Sunmi V2), il reste 420dp pour les resultats, moins la bottom nav (80dp) = 340dp. C'est serre.

Aujourd'hui — 4 controles empiles
  1. SegmentedButton 7j / 30j
  2. Dropdown provider
  3. Dropdown slot (disabled si pas de provider)
  4. Date picker
Propose — filtres condensables
  1. Chips horizontaux scrollables (7j, 30j, date custom)
  2. Un seul dropdown cascading provider → slot
  3. Ou : bouton "Filtre" qui ouvre un bottom sheet
Amelioration

Range par defaut invisible (2 jours)

Quand aucun filtre de periode n'est selectionne, les resultats montrent les 2 derniers jours. Mais cette plage par defaut n'est pas communiquee — le machann ne sait pas ce qu'il regarde. Ni "7j" ni "30j" n'est selectionne dans le segmented button.

Selectionner un preset par defaut (ex: 7j) au lieu de laisser rien selectionne. Ou afficher un label "2 dènye jou yo" quand aucun filtre n'est actif.
Point fort

Lots affiches en chips colores

Les numeros gagnants sont affiches en chips : couleur primaire pour les lots disponibles, couleur neutre avec "x" pour les lots manquants. Double signal couleur + texte pour l'accessibilite.

9. Rapò — statistiques vendeur

Ventes, tickets, commission par jour et par tirage

Amelioration

Max 50 tickets sans pagination

La section tickets du rapport charge au maximum 50 tickets (size: 50). Pas de bouton "load more", pas de message "50+ tikè — montre premye 50 yo". Un machann actif qui vend 200 tickets/jour voit un rapport tronque sans le savoir.

Ajouter un compteur total du serveur + pagination infinie, ou au minimum un message "Montre 50 sou {{total}} tikè".
Amelioration

Filtrer par tirage ne met pas a jour les totaux

Quand le machann filtre les rapports par tirage via les chips, les totaux en haut (ventes, tickets, commission) ne changent pas — ils montrent toujours le total de la journee. Le machann pourrait croire que le total correspond au filtre actif.

Soit recalculer les totaux selon le filtre, soit afficher clairement "Total jounen an" avec un separateur visuel avant la section filtree.
Amelioration

Pas d'export ni de partage

Le machann ne peut pas exporter ses statistiques en PDF, les envoyer par WhatsApp, ou les imprimer. Pour un machann qui doit rendre des comptes a son proprietaire de bank bolet, c'est un manque.

Ajouter un bouton "Pataje rapò" qui genere un resume texte partageable via le share sheet natif (WhatsApp, SMS).

10. Pwofil & Paramèt

Informations terminal, locale, impressions, notifications, PIN

Amelioration

Page profil read-only sans actions

La page profil montre terminal, compte et infos commerciales en lecture seule. La seule action est "Aller aux parametres". C'est un ecran informatif qui pourrait etre fusionne avec les settings pour eviter un ecran de plus.

Amelioration

Settings sauvegardent immediatement sans feedback

Chaque toggle (auto-print, notifications, copies) appelle le serveur immediatement via _updateSettings. Pas de spinner pendant l'appel, pas de confirmation de succes, pas de message d'erreur visible. Le machann toggle et espere.

Ajouter un bref feedback : spinner sur le toggle pendant l'appel, et snackbar "Anregistre!" en succes ou "Echwe — eseye ankò" en erreur.
Point fort

Selecteur de langue intuitif

Le SegmentedButton affiche les langues dans leur propre nom : "Kreyol", "Francais", "English". Le machann n'a pas besoin de lire une autre langue pour trouver la sienne. C'est le bon pattern.

Observations transverses

Patterns communs a toute l'app

Point fort

Design system solide et coherent

Tokens de spacing (s4 a s64), radius (xs a pill), couleurs semantiques (success, warning, error, blocked, online). Boutons avec taille minimum 48dp mobile / 56dp POS. Components: PosActionButton, SemanticActionButton, StatCard, StatusBadge, SurfaceCard, OnlineBadge. Tout est uniforme.

Point fort

i18n quasi parfaite

Sur 14 ecrans, un seul string hardcode en francais ("Copier code"), un fallback creole ("Tout li"), et un fallback ("Tiraj"). Le reste est 100% traduit via le systeme i18n. Les termes metier (Bolèt, Maryaj, Machann, Tiraj, Rezilta) sont corrects.

Friction

Pas de mode sombre

L'app n'a qu'un theme clair (TchTheme.light()). Les machann qui travaillent en soiree/nuit avec un ecran lumineux dans un espace sombre fatiguent les yeux. C'est aussi un probleme d'autonomie batterie sur les ecrans OLED.

Ajouter un TchTheme.dark() avec inversion des tokens surface/ink, et un toggle dans les settings ou le suivi automatique du systeme.
Friction

Dialog de logout duplique 3 fois

Le meme dialog de confirmation de deconnexion est copie-colle dans change_pin_page, cashier_home_page et seller_terminal_profile_page. Si le message ou le comportement change, il faut le modifier en 3 endroits.

Extraire un showLogoutConfirmation() partage.
Amelioration

Page Forbidden sans raison ni contact

Quand le machann est bloque, il voit un message generique sans explication (compte desactive ? region non autorisee ? abonnement expire ?). La seule action est se deconnecter. Pas de numero de telephone, pas de lien WhatsApp du gestionnaire.

Afficher la raison du blocage depuis l'API, et un lien de contact "Rele admin ou" avec le numero du gestionnaire configure dans le tenant.

Synthese

  • L'app mobile est bien construite. Le design system est solide, l'i18n est quasi parfaite, les tokens POS (56dp touch targets, posScale 1.15x) montrent une vraie reflexion sur le contexte terrain.
  • 5 actions P1 (corrections immediates) — le plus impactant est "Nouveau ticket → /sell" qui economise 1 tap x 200 ventes/jour = 200 taps inutiles par machann.
  • 8 actions P2 — surtout la performance du timer, les filtres resultats, et le feedback des actions.
  • 5 actions P3 — mode sombre, export rapports, maintenance.
  • Le vocabulaire metier est correct : Bolèt, Maryaj, Tiraj, Machann, Rezilta, Komisyon. Pas de renommage necessaire cote mobile (contrairement a l'admin ou "Limit", "Konfig kanal" etc. doivent changer).
  • Le flux de vente est globalement bon (pre-selection tirage, auto-advance, undo, preview) mais les chips sans feedback tactile et la double confirmation penalisent la rapidite des machann experimentes.
